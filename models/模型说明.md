# 模型说明

本目录**不存放模型权重**。权重体积约 10GB+，统一部署在 autoDL 远程 GPU 上，本机只保留推理代码与业务服务。

## 一、需要哪三个文件

项目使用固定的 Comfy-Org/MOSS-Image 工作流，缺一不可：

| 相对路径 | 用途 |
|---|---|
| `models/diffusion_models/moss_image_sft_int8_convrot.safetensors` | 扩散模型主体（int8 量化） |
| `models/text_encoders/qwen3.5_9b_w4a8_gptq.safetensors` | 文本编码器（9B，W4A8 GPTQ 量化） |
| `models/vae/flux2-vae_small.safetensors` | VAE 解码 |

来源仓库：`Comfy-Org/MOSS-Image`
固定版本（务必一致，换版本会导致工作流节点报错）：

```
REVISION = 530a4c94f92c35ef6818b1b035a983fe9dcf5f54
```

目录结构必须严格保持 `diffusion_models/`、`text_encoders/`、`vae/` 三级分类，因为 ComfyUI 按目录名归类模型。

## 二、在 autoDL 上怎么获取

推荐用 HuggingFace 官方 CLI，指定 revision：

```bash
pip install -U "huggingface_hub[cli]"
export HF_ENDPOINT=https://hf-mirror.com

hf download Comfy-Org/MOSS-Image \
  --revision 530a4c94f92c35ef6818b1b035a983fe9dcf5f54 \
  --include "diffusion_models/*" "text_encoders/*" "vae/*" \
  --local-dir /root/autodl-tmp/models
```

仓库根目录的 `download_models.py` 只适合"把权重放本机"的场景（它按 `.runtime/model-manifest.json` 校验 sha256、支持断点续传）。既然权重在 autoDL，这个脚本只需用来**取校验值**：

```bash
python download_models.py --preflight-only
# 输出 .runtime/model-manifest.json，其中每个文件都带 size 与 sha256
```

拿这份 manifest 到 autoDL 上核对下载结果：

```bash
sha256sum <文件>
```

## 三、autoDL 与本地服务怎么接

代码已改造为"引擎可插拔"，支持三种接法，按运维成本从低到高排列：

### 方案 A：SSH 隧道（最省事）

把 autoDL 的 8188 端口映射到本机 8188：

```bash
ssh -N -L 8188:127.0.0.1:8188 -p <autoDL_SSH端口> root@<autoDL地址>
```

后端看到的仍是 `http://127.0.0.1:8188`，属于"本地引擎"路径，取图走本地 `output` 目录的逻辑不会触发。启动时加 `--external-engine`，避免后端再去起一个本地 ComfyUI：

```powershell
python platform/serve.py --external-engine
```

优点：零配置、不暴露 ComfyUI（它本身无鉴权）。缺点：隧道断则推理断，需要保活。

> 注意：走隧道时，远端生成的图片仍然只在远端磁盘上，本机 `output/` 目录不会有文件。若隧道模式下取图失败，请改用方案 B（远程地址直连会自动走 `/view` 下载）。

### 方案 B：后端直连远端引擎（代码已支持）

后端可以把引擎地址指向远端，取图改为通过 ComfyUI 的 `/view` 接口下载，不再依赖本地目录：

```powershell
python platform/serve.py --external-engine --engine-url http://<autoDL地址>:8188
```

也可以不传参数，用环境变量：

```powershell
$env:MOSS_ENGINE_URL = 'http://<autoDL地址>:8188'
python platform/serve.py --external-engine
```

只要 hostname 不是 `127.0.0.1` / `localhost` / `::1`，就自动判定为远程模式：
- 结果图走 `GET /view?filename=...&subfolder=...&type=output` 下载；
- 本地 `output/` 目录不再参与。

**安全要求**：ComfyUI 无任何鉴权，直接暴露公网等于公开 GPU。必须叠加安全组白名单、VPN 或带鉴权的反向代理。

### 方案 C：整个服务搬到 autoDL

后端与 ComfyUI 同机，`engine_url` 保持默认，代码完全不需要改。本机只做前端开发或浏览器直接访问 autoDL。

| 方案 | 改配置 | 取图方式 | 暴露风险 |
|---|---|---|---|
| A SSH 隧道 | 无 | 本地 output 目录 | 无 |
| B 直连远程 | 一条参数/环境变量 | HTTP `/view` | 需自行加防护 |
| C 全搬到 autoDL | 无 | 同机本地目录 | 按需 |

## 四、可用的环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `MOSS_ENGINE_URL` | `http://127.0.0.1:8188` | 引擎地址，支持 http/https 远程 |
| `MOSS_INFERENCE_PYTHON` | 当前后端解释器 | 自启推理子进程时用的 Python |
| `MOSS_ENGINE_TIMEOUT` | `30` | 单次引擎 HTTP 超时（秒），远程/高延迟可调大 |
| `MOSS_DATA_DIR` | `platform/data` | 数据库与图片存放目录 |
| `MOSS_ALLOWED_ORIGINS` | 本机 5173/8000 | 允许的跨域来源，逗号分隔 |
| `MOSS_SECURE_COOKIE` | `0` | 置为 `1` 时 Cookie 仅走 HTTPS |
| `MOSS_BOOTSTRAP_ADMIN` | `1` | 空库时是否自动创建默认管理员 |
| `MOSS_PYTHON` | 本机 conda 环境 | 启动脚本使用的后端解释器 |

## 五、本机还需要注意

- `extra_model_paths.yaml` 的 `base_path` 已指向本目录（`D:/ProjectAll/trae_case/ImageGeneration/models`），仅在本机跑引擎时生效；模型放到 autoDL 后，把同名文件同步到 autoDL 并改 `base_path` 即可。
- 4GB 显存（RTX 3050 Ti Laptop）+ 16GB 内存是硬约束，本机**不应该**再启动本地 ComfyUI，否则显存互相挤占。
- 工作流 JSON（仓库根目录 `workflow-api*.json`）里写的是文件名而非路径，只要 autoDL 上目录结构正确，工作流无需修改。
- 本目录只保留本说明文档，权重文件一律不入版本库（`.gitignore` 已配置 `/models/*` 忽略、仅放行本文件）。
